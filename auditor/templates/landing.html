The gap

Fairness toolkits need the model.
Employers only get a login screen.

NYC Local Law 144 requires bias audits of automated hiring tools, and the EU AI Act classes recruitment AI as high-risk. But the model, data and code belong to the vendor.

Model-side fairness libraries

  • Need the model weights or an API
  • Need the training or test data
  • Run once, in a notebook
  • Can't see what the interface actually does

Fairness Auditor

  • Needs a URL and one sentence
  • Uses synthetic CV twins, no real data
  • Runs on every release and blocks bad deploys
  • Tests the product people actually use, with evidence
How it works

Four steps, no access required

Write twins

Identical CVs that differ only in name and pronouns: male/female × two name groups, from the classic Bertrand & Mullainathan study.

Add a placebo

A second name from the same group. If that moves the score too, the tool reacts to names, not demographics.

Kane drives the UI

Kane CLI opens the real tool, submits every CV from a one-line task, stores each score and decision, and seals evidence.

Verdict gates deploys

PASS, BIASED or NAME-UNSTABLE, as an exit code. CI blocks the release until the tool is fixed.
